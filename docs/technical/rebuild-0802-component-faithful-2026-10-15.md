## 三、More Love 的关键交叉验证

本轮一开始怀疑「上游在同名 tag 下换过资产」，因为 0713 原件里的
More Love 槽是 10,592 B，而今天从 `v0.1.6.0` 下到的是 10,473 B。

实际原因不是换资产，而是**构建期补丁**：`lyra/build.py` 会对 More Love
应用「drag 事件防御性补丁」（`more_love_drag_event_handlers`，
fail-closed），产出 `<name>-<pack>-<code>.patched.mod.zip`。

把 0802 重建件的 More Love 槽与 **0713 原件**的对应槽做字节比较：

```
0802 重建件槽 26 : 10,592 B  sha256 f8132de3d1f1479a…
0713 原件槽 25   : 10,592 B  sha256 f8132de3d1f1479a…
→ 逐字节相同
```

也就是说：上游 `v0.1.6.0`（10,473 B）+ 本项目补丁 = 10,592 B，
与 7 月的原件完全一致。这同时确认了补丁输出的稳定性，
以及 0802 用的就是同一个上游资产。

## 四、ZIP 差 1–8 字节的原因

0802 原件的 Lyra 元数据 zip（槽 38）时间戳不可考。为判断它能造成多大偏差，
用 0804 重建件做了对照实验（0804 的时间戳是已知精确值）：

```
shift   +0 min → deflate 89,739,284
shift   +1 min → deflate 89,739,279
shift   −1 min → deflate 89,739,283
```

即：Lyra zip 时间戳每变化 1 分钟，打包后的 HTML 体积可变化约 5 字节
（压缩器对字节变化的自然抖动）。因此 0802 ZIP 的 +1 / −8 字节残差
与「时间戳估算存在偏差」完全一致，不指向内容缺失。
