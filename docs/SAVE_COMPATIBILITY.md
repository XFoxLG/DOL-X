# 存档兼容性策略

## 原则

- 存档兼容性难以自动化测试
- mod 更新、游戏更新都可能破坏存档
- 建议用户定期备份存档

## 手动测试清单

添加新 mod 后：

1. **加载旧存档** → 验证无崩溃
2. **保存新存档** → 刷新页面 → 加载 → 验证成功
3. **测试核心功能**：战斗、存档、统计

## Breaking Changes 记录

### 2026-06-12：cheatExtended 替代旧作弊栈

- **变更**：将 cheat_csd (bit 2) 替换为 cheat_extended_maplebirch (bit 32768)
- **影响范围**：主线构建 build_codes 从 24834 系列变更为 57346 系列
- **存档风险**：中等（作弊系统变更可能影响存档中的作弊相关状态）
- **缓解措施**：
  - 功能完全等价，不丢失作弊能力
  - 建议用户在切换前备份旧版本存档
  - 如遇问题可回退到旧 build_codes（24834、25858、26882、28930）

## 用户教育

### README 中的提示

建议在 README.md 添加以下内容：

```markdown
## ⚠️ 存档备份提醒

- **定期备份存档**：mod 更新、游戏更新都可能影响存档兼容性
- **大版本更新前必须备份**：尤其是更换作弊系统、框架等核心 mod 时
- **存档位置**：
  - 浏览器版：浏览器 LocalStorage/IndexedDB
  - APK 版：Android 内部存储 `/sdcard/Android/data/com.vrelnir.dol.xfox/files/`
```

### 更新日志中的提醒

每次发布新版本时，如果有潜在存档兼容性风险，在 Release Notes 中明确标注：

```markdown
## ⚠️ 存档兼容性提示

本次更新包含 [具体变更]，可能影响存档兼容性。

**推荐操作**：
1. 备份当前存档
2. 测试新版本
3. 如遇问题，回退到旧版本并恢复存档
```

## 自动化测试的局限性

### 为什么存档兼容性难以自动化？

1. **存档状态空间巨大**：
   - 游戏进度、角色属性、事件状态组合数极大
   - 难以覆盖所有可能的存档状态

2. **Mod 组合爆炸**：
   - 不同 mod 组合产生的存档结构不同
   - 需要维护大量存档样本

3. **变更类型多样**：
   - 游戏逻辑变更（DoL 本体更新）
   - Mod 数据结构变更（mod 版本更新）
   - 框架 API 变更（ModLoader/框架更新）

4. **验证困难**：
   - 存档加载成功 ≠ 游戏逻辑正确
   - 需要深度游玩验证（难以自动化）

### 当前测试覆盖范围

当前自动化测试**只保证**：
- ✅ ModLoader 不崩溃
- ✅ Mod 加载成功
- ✅ 页面可渲染并进入游戏

当前自动化测试**不保证**：
- ❌ 旧存档可加载
- ❌ 游戏逻辑正确性
- ❌ 跨版本兼容性

### 推荐策略

- **自动化测试**：覆盖 ModLoader 启动和基础渲染
- **手动测试**：按本文档清单验证核心功能
- **用户反馈**：收集社区报告的存档问题
- **版本锁定**：记录已测试的 mod 版本（`mods.lock.json`）
